# 小组日常协作

每人独立开发，准备好就提交PR；不需要等全组某个统一日期才合入。默认自动合并不要求指定审核人。D7仍是全组集成验收节点，不是禁止提前合并的日期。

## 认领与提交

1. 打开本人[任务单](https://github.com/yuge2018/nlp-gender-bias-detection/issues)，在右侧Assignees选择自己的GitHub账号；或让拥有写权限的组员代为设置。
2. 从最新main创建自己的分支。建议`part/p1-data`至`part/p6-demo`，也可以使用自己的命名或Fork。只按接口交接，不导入其他模块内部实现。
3. 编写本人代码、配置、测试和报告片段。在本地按任务书验收，再推送并创建PR，正文写明`Closes #任务编号`可在合并后自动关闭任务。
4. 完成的PR使用Ready状态，检查通过后自动合并；未完成先用Draft。合并后按需继续原分支或另开新分支，系统不自动删除分支。

```sh
git switch main
git pull --ff-only
git switch -c part/p3-improved
# 完成自己的实现和测试
git add <本次文件>
git commit -m "[P3] 完成改进模型适配器"
git push -u origin part/p3-improved
```

也可在自己的Fork开发，再向本仓库main提交PR；是否自动处理取决于作者在本仓库的当前权限，不取决于分支存在哪个账号下。

## 自动与人工的切换

| 当前意图 | 做法 | 结果 |
|---|---|---|
| 已完成，希望自动合并 | Ready PR，不带`manual-merge`标签 | 自动排队，必需检查通过且无冲突后合并 |
| 尚未完成，想提前展示 | 创建Draft或转回Draft | 保持草稿，不自动合并 |
| 已完成，但想自己决定合并时机 | 加`manual-merge`标签 | 取消已有自动合并请求，保留人工决定 |
| 恢复自动处理 | 转Ready并移除`manual-merge` | 重新按必需检查处理 |
| 想保留其他合并方式 | 在GitHub原生自动合并中选择Merge或Rebase | 工作流保留已选方式；首次默认Squash |
| 检查失败或存在冲突 | 查看失败日志或处理冲突后推送 | 重新检查；通过前不合并 |

需要暂停时，最好从Draft开始；标签操作在对应工作流执行后生效，已经合并的PR不能靠加标签撤销。`manual-merge`只控制自动流程，手工合并仍要通过必需检查。

main不要求每个PR随时追上main的每次更新，减少不同模块互相等待。若出现冲突，可以用页面的Update branch（可用时）或在自己的分支合并最新main；无需强推main。若改动共享接口，仍按接口文档明确版本和兼容方案。

## 检查范围

`contracts`工作流并行运行：

- **contract-tests**：无外部依赖的Python契约/可用模块测试、自动合并行为测试、6模块mock入口。
- **baseline-tests**：在独立Python3.12环境安装P2锁定依赖，用小样本执行P2真实训练、预测与失败输入测试；不下载完整数据、不做正式实验训练、不需要GPU。
- **interfaces**：汇总前两项；两项都成功才放行main合并。检查名保持不变，避免要求成员学习新的合并步骤。

各人仍需在自己的环境完成任务书要求的真实实验、日志和数据版本验证。GPU训练、全量调参及报告中的正式成绩不由上述轻量CI代替。检查完成后会自动重新处理对应PR；GitHub短暂的合并状态波动不会要求成员反复手动点开关。新增真实模块时，可增加独立测试任务，保持不同成员的依赖隔离。

## 权限与仓库公开

仓库按用户要求公开。明确邀请加入的成员默认取得当前个人仓库可授予的最高协作者权限write，可推送分支、认领任务、提交和合并PR。个人仓库的设置管理仍属于拥有者。

自动合并只面向当前有write及以上权限的作者。公众可以查看和提出PR，但无写权限作者的PR不自动合并。特权工作流只调用GitHub接口，不检出或执行PR代码。

原始/处理数据、权重、缓存和密钥继续保持忽略；公开仓库中保留可复现脚本、校验值、统计和报告。参考[接口约定](INTERFACES.md)和[最终交付清单](INTEGRATION.md)。
