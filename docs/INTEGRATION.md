# 集成与最终交付

## 各自开发

```sh
git clone https://github.com/yuge2018/nlp-gender-bias-detection.git
cd nlp-gender-bias-detection
git switch -c part/p1-data
python -m unittest discover -s tests -v
python -m src.data --mock --output-dir runs/p1-smoke
```

按本人编号替换分支和模块。每人只改独占目录、本人配置/测试/依赖与报告片段。共享契约要改时通过P4维护的PR处理。无需等待其他模块真实完成才提交PR。

环境独立：契约检查无外部依赖；各人安装`requirements/pn.txt`。P3的torch/CUDA版本依硬件确定并记录。P6使用懒加载适配器，不选深度模型时不要求安装深度模型环境；正式集成时P6整理实际验证过的统一依赖锁文件。

## 日常合并

仓库已公开，成员Ready PR默认在`interfaces`检查通过后自动合并，不强制指定审核人；成员可以使用本仓库分支或自己的Fork。未完成先用Draft，需保留人工决定时加`manual-merge`标签，准备好后恢复Ready并移除标签。完整操作见[小组协作说明](WORKFLOW.md)。

接口、真实CPU模型测试和mock兼容检查会自动执行；不在CI中强制跑完整数据训练或GPU实验。D7是集中验收节点，已完成的模块可以提前合并。

## 三次交接

1. **D1数据/接口冻结**：P1核对来源和转换；P4核对契约；确认类含义、字段、Macro-F1和原split。其他人从fixture开工。
2. **D7模块验收**：各模块通过本人测试与统一契约检查。P4/P5只接run文件；P6只接适配器。真实run的`is_mock=false`、数据hash完全相同，输出可追溯到配置与提交。
3. **D10最终复现**：换新目录按文档运行；预测行数和ID一致；离线加载两模型；演示两条针对男性/女性的偏见例句与两条无偏见/反驳例句，不挑选演示结果充当统计结论。

## 合入清单

- [ ] 本模块可单独运行，真实模式不依赖其他模块内部实现。
- [ ] 有有效与失败输入验证，含标签映射、顺序或数据hash等相应风险。
- [ ] 所有mock示例保留显著标识，正式比较拒绝mock。
- [ ] 不提交原始语料、模型大权重、缓存、密钥或他人实验作业。
- [ ] 预测、日志、配置、环境、manifest hash与代码提交均可对应。
- [ ] 本人报告片段、图表、贡献和答辩要点齐全。
