## 系统与演示

演示系统是仓库内的本地 Streamlit 应用 `src/demo/app.py`，打开后有两个页签：
**单句检测**（选择模型 → 输入文本（每行一条）→ 按 `predictor.predict_proba` 取分 → 按阈值判 0/1）
与 **真实结果（只读）**（直接浏览仓库里已入库的真实评测 run）。
两个页签都不训练模型、不读取测试金标做预测、不计算任何指标，也不判断句子的作者性别。

系统按“可变点配置化”拆成五层，避免在 D7 接入真实产物时返工：

| 层 | 文件 | 职责 |
|---|---|---|
| 页面 | `src/demo/app.py` | 唯一 import streamlit 的文件：双页签、模型下拉、输入、结果、阈值、mock 横幅、错误面板、结果浏览 |
| 注册表 | `src/demo/registry.py` | 读 `configs/demo/default.json`，按冻结契约 `load_predictor(model_dir, *, mock=False)` 懒加载；提供模型四态；缺目录/缺权重/缺依赖/缺适配器统一转成带建议的 `ModelUnavailable` |
| 打分 | `src/demo/scoring.py` | 输入、阈值、分数的边界校验；生成 `id/text/score/label` 行并保持输入顺序 |
| 结果浏览 | `src/demo/results.py` | 只读遍历 `runs/**`，校验并汇总已入库的 `metrics.json`；默认排除 mock；坏文件不崩 |
| 图表 | `src/demo/figures.py` | 只读 P4 的 `metrics.json` 冻结字段出图，mock 图文件名自动加 `mock_` 前缀 |

模型清单写在配置里（`configs/demo/default.json` 的 `models`），每项包含
`key / display_name / adapter_module / model_dir / is_deep`，可选 `probe_files`。因此增加或替换模型只改 JSON，
页面代码不动；`adapter_module` 为 `null` 的条目是开发替身。

**“目录存在”不等于“模型可用”**：权重是否入库因模型而异——P2 baseline 的 `model.joblib` 已入库，
P3 improved 目录目前只有 `model_metadata.json`。`registry.model_status` 因此返回四态——
`mock`（替身可用）、`ready`（目录内有真实载荷，`probe_files` 指定的文件也都存在）、
`weights_missing`（只剩元信息或必需权重缺失）、`missing`（目录不存在）。`is_available` 仅在
`ready` / `mock` 时为真；页面下拉框分别标注“权重未就绪 / 模型目录未就绪”，`load_model` 在导入
适配器前先按状态分流，权重缺失时直接给出“请在本机重新生成或向负责人获取 artifacts”的建议，
而不是让用户看到 ImportError。

**模型切换**：选择真实模型时，`registry` 先判定状态，再动态导入该角色的 `adapter` 并调用
`load_predictor`；加载成功后用同一 `Predictor` 协议打分。页面从不 import torch，
也不接触 tokenizer、TF-IDF 或任何模型内部实现，深度模型未就绪时页面仍可正常打开。

**真实结果页签**：只读 `runs/**`，用 `figures.load_metrics` 校验 P4 冻结字段；默认跳过
`is_mock=true` 的 run 并显示跳过数量。坏 `metrics.json` 归入“无法解析”并显示原因；
只有 `predictions.jsonl`、尚无 `metrics.json` 的目录归入“待评测”。列表中的
`n / macro_f1 / positive_f1 / 混淆矩阵 / 阈值 / 方法` 全部取自文件，页面不重算，
仅在展示时保留 4 位小数；选中单个 run 可展开 JSON 详情逐字段追溯。这样即使本机没有权重，
演示也能展示仓库中已复核的真实证据。

**分数口径**：显示值是适配器返回的“有偏见（1）的模型分数”，页面固定注明
“未做概率校准，不等同于客观偏见概率”。判定用 `label = int(score >= threshold)`，
默认阈值取配置的 0.5；若模型元信息记录了阈值，页面同时显示记录值。页面不修改分数、
不四舍五入参与判定，也不把演示分数写成实验结论。

**mock 与失败处理**：开发替身（`MockPredictor`）固定输出 0.5，结果区以红底横幅声明
“没有任何检测能力”，避免把示例分数误读成模型表现。真实模型缺失时，页面给出
“模型目录不存在 / 适配器模块导入失败 / 缺少运行依赖”的具体原因与修复建议，而不是抛出异常退出。
`python -m src.demo --mock --output-dir runs/p6-smoke` 保留仓库既有的 mock 冒烟行为，供 CI 使用；
真实入口单独为 `streamlit run src/demo/app.py`。

**演示内容**：内置四条自编演示例句（`configs/demo/examples.json`），分别覆盖
针对男性的角色限制、针对女性的职业判断、中性事实描述、引用并反驳偏见。
这四条来自 `docs/TASK_SCOPE.md` 的接口讨论示例，**不是官方金标，不参与任何指标或阈值选择**，
也不能用来推断数据对男性/女性/其他性别身份的覆盖程度。

## 局限与答辩要点

**局限**：

1. 演示是本地单页程序，不提供服务化部署、并发或用户管理；答辩只需证明离线可运行。
2. 真实模型可用性因角色而异：baseline 权重已入库，可现场推理；improved 权重未入库，
   本机“单句检测”选 improved 只会得到“权重未就绪”。真实证据仍通过
   “真实结果（只读）”页签从 `runs/**` 展示。
3. 页面分数未做概率校准，阈值可临时调整；任何“准确率/公平性”结论只能来自 P4/P5 的评测文件。
4. 四条演示例句是自编接口示例，不能代表数据分布与性别对象覆盖；覆盖问题由 P5 的挑战集回答。
5. 主表现已由 P4 生成并入库；P3 其余五个改进变体的权重与 run 目录不入库，主表只有 I2 一个改进点，P6 如实标注、不代算。
6. 老师未提供报告与 PPT 模板，版式由本组自定；P6 负责内容组装与统一叙事，页数与时长按课设要求自控。

**答辩三问**：

1. *界面怎样切换模型？* —— 模型清单在 `configs/demo/default.json`，下拉框选中后由注册表按四态
   判定、动态 `load_predictor` 并缓存；页面不感知模型内部，新增模型只改配置。目录存在但权重缺失时，
   页面明确显示“权重未就绪”，不会把空目录当成可用模型。
2. *没有权重怎么演示真实结果？* —— “真实结果（只读）”页签只读 `runs/**` 里已入库的
   `metrics.json`，默认排除 mock，字段全部取自文件；坏文件与待评测目录分开列出，不崩也不猜。
3. *为什么不把分数称为事实概率？* —— 契约只要求 `predict_proba` 返回 `[0,1]` 的 label=1 分数，
   未做概率校准；把它说成“客观偏见概率”会误导，因此页面统一标注“未校准的模型分数”。

**追溯方式**：每个 run 目录保存 `predictions.jsonl`、`run_metadata.json`
（含 `dataset_manifest_sha256`、`code_commit`、`seed`、`threshold`、`model_revision`）与 P4 写的
`metrics.json`；ID 与输入逐行对应，报告中的每张表都能指回这些文件，页面详情里的
`data_hash` / 混淆矩阵可逐字段核对。
